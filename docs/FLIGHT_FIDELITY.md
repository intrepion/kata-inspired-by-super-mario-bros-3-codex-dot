# Run-up and powered-flight correction

Research before design: Nintendo's [original NES manual](https://www.nintendo.co.jp/clv/manuals/en/pdf/CLV-P-NAACE.pdf), printed pp6–8 (PDF pp7–9), was downloaded/read as scanned pages. It separates walking from held-B acceleration, increases a visible power meter with continued speed, and enables limited flight through repeated A presses at full power. The [official Famicom overview](https://www.nintendo.com/jp/famicom/software/smb3/index.html) independently identifies speed-built power, temporary flight and slow falling. All assets/story remain original.

Settled recommended defaults: retain the existing 290px/s as run speed, add 170px/s walking, preserve acceleration/braking and variable jump, fill a six-part meter only at running speed on solid ground. With sail/full power and a real ground jump, start three seconds of powered flight; each new jump press provides an upward flap. Held jump still glides after flight expires. Reversal/braking drains power, stationary or air input cannot charge, and landing/hurt/retry clears flight. A one-way upper cloud ledge in Glass Orchard rehomes existing optional motes/seal, keeps stable reward IDs and the 28-mote cap, and leaves the lower route available. No save-format change is needed because only completed-trail meta-progress is persisted.

The authored numbers are bounded approximations rather than exact Nintendo physics. User-delegated Grill with Docs / Implement defaults are recorded here, not presented as interview answers. Implementation checks and the completed bounded normal-input route are recorded below.

## Implementation and evidence

The simulation owns walking/running acceleration, the actual-speed charge predicate, power loss, takeoff eligibility, flaps and timeout. Blocked walls and the world boundary cannot charge. Keyboard and pointer Run sources combine through the established independent input maps, so releasing one source preserves other held sources. Focus loss clears input and pauses with the existing fixed-clock reset. Touch has named Hold Run and Jump / Flap controls. The DOM status and six-part canvas meter display power or remaining flight; camera Y follows high ascent so flight remains visible. The upper ledge is one-way, unlike solid old platforms. Its relocated two motes and moon seal keep their original stable IDs and the 28-mote total.

The first six new behavioral tests were observed failing before implementation, then passing alongside all original regressions. They cover walk/run caps, ground-speed charge, collision/boundary non-charge, reverse takeoff denial, no standing/unpowered flight, held-vs-tapped flaps, timeout, landing/injury/retry reset and one-way landing. A movement-only flight solver starts at normal Glass Orchard entry, acquires the feather at x220 normally, runs to full power near x496, uses four jump presses per second and reaches the cloud seal/landing with zero deaths. Existing seven-exit solvers explicitly hold Run and still finish without requiring the sail. These simulations are not browser evidence. Strict TypeScript, production build (`index-CWs21QtO.js`) and `git diff --check` also passed. Independent Standards and Specification reviews passed. ## Planned ordinary-input acceptance route

1. At http://localhost:5209 enter First Light; compare walking with holding Shift/X and observe charge rise at speed. Brake or reverse and observe it drop. Finish First Light and Reedwater with ordinary jumps to unlock Glass Orchard, or replay it from an existing legitimate save.
2. In Glass Orchard collect the visible feather near entry by running right. Keep holding Run along the clear lower ground until the meter shows full power (near the first gap between upper ledges). Jump while running, then release/press jump about four times per second for powered ascent. Continue moving right beneath/around the old ledges, then rise through the cream cloud platform above them.
3. Near the cloud moon seal, brake by releasing horizontal input or steer slightly left; stop flapping once above the cloud. Hold jump on descent to glide and land on the platform. Touch the blue moon seal and verify the reward cue. Remaining flight must decrease continuously, then permit only falling/gliding until another legitimate run-up.
4. Drop to the safe lower route; fall/retry once and confirm the feather and earned expedition rewards remain, while power/flight reset. Finish the trail. Return to the map, reload, and verify completion, best rewards and seal persist. Saved earlier completed trails remain unlocked.
5. Test a keyboard Run hold together with a pointer Hold Run; release either one and confirm the other still runs. Pause or blur mid-flight and resume without a held key or time jump. Test the touch control layout when the viewport offers it.
